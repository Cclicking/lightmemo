# 根据手机日志进行定向优化

依据同日识别日志：完整任务 97.473 秒，首次模型 42.024 秒，复核模型 26.314 秒，营养匹配 29.110 秒。模型输出 12,995 token，其中思考 12,012；USDA 五次请求返回 4,472,994 字节。这是优化前单次手机实测。

## 模型请求

对 HTTPS 的 `api.deepseek.com` 且模型名为 `deepseek-flash` 的请求显式发送 `thinking: {"type":"disabled"}`。两次图片请求和复核仍然执行，照片尺寸、提示词、结果校验和匹配条件保持原有逻辑。其他服务商和模型不附加这一厂商参数。

同时将 temperature、max_tokens 改为必须序列化的请求字段，实际发送原代码指定的 0.1 和 3000。原来的默认值会被默认 JSON 配置省略；日志中单次输出超过 3000 token 与这一问题一致。

DeepSeek 官方参数依据：https://api-docs.deepseek.com/guides/thinking_mode/

## USDA 请求参数丢失

原 `SearchRequest` 将 `dataType` 和 `pageSize=8` 定义为 Kotlin 默认值；默认 `Json.encodeDefaults=false` 时，自动匹配请求只包含 query。手动搜索的 pageSize 如果不是 8 会发送，但类型筛选仍被省略。

USDA 文档规定 pageSize 未指定时默认为 50，dataType 未指定不限制类型。修复后两个参数都是必需序列化字段，自动匹配发送 pageSize=8 及 Foundation / SR Legacy / Survey (FNDDS) 三类；手动搜索仍按请求数量，保留 1–50 的原范围。

自动匹配候选上限由服务端默认的 50 改为预期的 8，上限减少 84%。这不是实测响应字节数或耗时减少 84%；实际结果数、类型分布、网络和排名都会影响结果。原来的候选匹配阈值、生熟与菜谱校验保持执行。候选范围收窄可能影响个别查询的召回，应使用同图结果做对比，未通过校验的条目仍需人工确认。

官方请求规范：https://api.nal.usda.gov/fdc/v1/json-spec?api_key=DEMO_KEY

## 验证与手机复测

新增测试直接截获 HTTP 请求 JSON，验证官方 Flash 两次图片请求均禁用思考、其他提供商/模型不携带该参数、模型生成参数显式发送、USDA 的 8 条/20 条候选及三类筛选确实发送，并验证匹配能正常返回。

日志新增 `thinkingDisabled` 和 `candidateLimit`，不记录任何新增业务内容。保持“查看日志”入口已移除，日志仍可导出。

复测时开启日志，使用同图并选择重新识别；核对三项阶段耗时、任务总耗时、思考 token 与 USDA 响应字节，并对比菜品、组成、重量和匹配条目。本地测试验证请求和规则行为，不代表真实服务端提速。

两次模型请求均记录 `thinkingDisabled=true`，实际输出各 685 token，未返回思考内容或思考 token 字段。保留两次图片模型调用，两个模型阶段合计从 68.338 秒降为 5.526 秒，耗时下降 91.91%。这支持关闭思考后的模型等待明显减少，但缺失思考计数字段不应写成已测得 0 token。

新图片任务没有 USDA 在线请求，营养匹配仅用 5 ms，说明这次走本地或缓存路径；不能用这次结果证明 USDA 在线响应体已经缩小或在线查询已提速，仍需出现 `provider=USDA`、`candidateLimit=8` 的新请求才能核对。
