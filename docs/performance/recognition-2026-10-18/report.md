# 识别速度对比

基线：`d7c98c0f39920bfc91f76cf1048dacdd47503764`；对比当前工作区。
同一 JVM 交替测量，先预热两轮；下表为多次运行的中位数，单位毫秒。
真实离线库；网络场景使用固定延迟模拟响应，不访问互联网。

| 场景 | 优化前 | 优化后 | 耗时减少 | 请求次数（前→后） |
| --- | ---: | ---: | ---: | --- |
| 离线首次匹配（6 组，含库加载） | 493.23 | 142.27 | 71.2% | 0 → 0 |
| 离线候选搜索（12 组，库与索引已加载） | 975.92 | 30.21 | 96.9% | 0 → 0 |
| 整餐离线匹配（12 组成，6 个不同查询） | 503.90 | 11.38 | 97.7% | 0 → 0 |
| 整餐在线回退（8 组成，每次 HTTP 模拟 120ms） | 1987.62 | 248.40 | 87.5% | 16 → 4 |
| 文字识别核心流程（模型 150ms＋数据库 HTTP 120ms，均模拟） | 2139.63 | 403.92 | 81.1% | 17 → 5 |

## 条件与边界

- 每组先预热两轮，随后交替先运行基线/当前版；冷加载项每次新建客户端，包含离线库与索引初始化。
- 候选搜索没有查询结果缓存；整餐离线匹配在计时前加载库/索引，但查询缓存为空。
- 在线回退使用 8 个组成、4 个不同的未知查询；返回空 foods，单次 HTTP 固定等待 120ms。
- 文字核心流程增加一次 150ms 模型响应与真实 JSON 解析；不含 Android Service、页面展示和磁盘保存。
- 原版源文件由 git show 提取，仅重命名类型以与当前实现共存；数据库资产相同。
- JVM：21.0.12.1；系统：Windows 11；可用处理器：20。
- 原始样本、各组样本数与 P95 保存在同目录 results.json；样本数量较少，P95 仅用于观察波动。
- 所有对比场景均核对候选顺序或匹配结果一致；耗时不包含 Gradle 编译和测试启动。
- 未测手机页面首帧、真实图片编解码及真实模型响应，不能据此承诺手机端到端提速比例。

复现命令：`python tools/benchmark_recognition.py --baseline d7c98c0f39920bfc91f76cf1048dacdd47503764`。

库冷加载指新客户端第一次加载数据库与索引；JVM 已预热，不包含应用进程启动，未清空系统文件缓存。
