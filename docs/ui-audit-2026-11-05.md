## 核心判断

当前阻碍完成度的主要问题是：主任务被可选信息挤压；同一信息重复展示；页面把使用规则、配置细节和后果写成说明段落；草稿、保存与返回没有统一契约。

精简应从任务结构开始。把一段说明删掉，却保留需要它解释的交互，会让界面更难使用。可见文字可以减少，但控件标签、单位、关键状态、无障碍名称、错误原因和数据处理后果仍需清楚。

优先级：P1 为记录可靠性或明显阻断；P2 为主要流程、理解成本和操作质量；P3 为实现收敛与次要页面打磨。每项设计建议都保留原有能力，改变的是默认呈现和进入方式。

## 优先修复的问题

### 01 · P1 · 修改总营养后，保存会删除组成数据

证据：`ui/screens/EditFoodScreen.kt:471–501`。当总营养与组成计算值不同，页面显示一条脚注，保存时执行 `candidate.copy(components = emptyList())`。`ui/screens/addfood/AddFoodManualEdit.kt:495–520` 存在相同处理，手动录入和预设编辑也受影响。

影响：用户只想纠正热量，却会失去成分、重量与匹配来源；一条辅助说明承担了数据丢失的告知责任。

改法：保留组成和明确的总营养覆盖值；展示“按组成计算 / 手动数值”这一实际状态，允许恢复计算。若当前模型无法支持，至少在发生冲突的当下提供明确选择，不能只在页尾告知后自动清空。

验收：改总热量、保存、重开后组成仍在；恢复计算可得到原组成合计；备份和导出往返保留覆盖状态。

### 02 · P1 · 编辑记录的草稿与退出行为不可靠

证据：`EditFoodScreen.kt:105–110` 使用 `remember(entry.id)` 持有草稿；`ui/secondary/SecondarySettingsActivities.kt:129–131` 顶栏返回直接 `finish()`；编辑页没有自己的未保存退出保护。相比之下，管理食物卡片页已有 `requestBack()` 和放弃确认。

影响：返回会直接丢弃编辑；Activity 重建时页面内草稿没有保存机制。两个相近页面的退出规则不同。

改法：由编辑状态持有者管理可恢复草稿和 dirty 状态，统一系统返回、顶栏返回及保存中的行为；无改动直接退出，有改动提供保存或放弃。

验收：修改名称、份量、成分后分别测试顶栏返回、系统返回和 Activity 重建；草稿不静默丢失，保存只执行一次。

### 03 · P1 · 「加入预设」使用原记录，忽略屏幕上的编辑

证据：`SecondarySettingsActivities.kt:433–440` 从 `editVm.uiState.entry` 加入预设，而当前编辑保存在 `EditFoodScreen` 的局部 `draft` 中。

影响：修改名称或份量后点图钉，预设仍可能是修改前的数据。按钮作用对象与用户看到的对象不一致。

改法：预设操作读取同一个有效草稿；存在无效输入时阻止操作并定位字段。保存记录和加入预设共享校验后的数据，不需要新增一套表单状态。

验收：改名、改份量、改成分后加入预设，预设内容与当前界面一致。

### 04 · P1 · 未配置识别时，给出不存在的导航路径

证据：`addfood/AddFoodPickSource.kt:138–142`、`AddFoodManualEntry.kt`、`AddFoodChat.kt:120` 使用「我的 → 识别 API」；实际入口在 `MainActivity.kt` 推荐页右上角，名称是「AI设置」。

影响：首次使用者被引向错误入口。配置缺失卡片不可直接解决问题，还占用了主要录入空间。

改法：缺失状态提供可点击的「配置识别服务」，直接进入配置页；返回后恢复录入上下文。相机、相册、快捷输入和对话识别复用同一配置检查及跳转。

验收：从每个入口在未配置状态开始，均可直接配置并回来继续，名称和路径完全一致。

### 05 · P2 · 统计把超过目标的百分比显示为 100%

证据：`StatsScreen.kt:967–982` 先把进度限制为 `0..1`，再用它生成百分比文字。

影响：实际达到目标 150% 时，环内仍是 100%。图形允许封顶，数值不应随图形一起被截断。

改法：分别计算真实比值与绘制进度；显示真实百分比或超出量，保留准确值和目标值。

验收：0%、100%、150% 和异常目标值都准确显示，文字与图形含义一致。

### 06 · P2 · 热力图交互过密，指标切换没有可见操作线索

证据：`StatsScreen.kt:1051` 的热力格为 10dp，`HeatmapCell` 直接附加点击；`DailyMetricTitle` 让普通标题点击后循环四个指标。

影响：密集小格容易选错日期；普通标题看不出能切换，也看不出有哪些指标。点击区域实际扩展和重叠情况需设备验证。

改法：热力图保留概览密度，用整图触摸定位加日期详情或另一个可准确选择的日期控件；指标改为短名称加展开符号的选择器。现有语义描述继续保留。

验收：单手能稳定选择相邻日期；无需阅读提示就能找到四种指标；TalkBack 能读出日期、指标和值。

### 07 · P2 · 小组件编辑同时采用即时保存和「保存」按钮

证据：`widget/WidgetSettingsActivity.kt:224` 点击动作立即写入；`:269` 圆角拖动结束立即写入；边距也立即写入；`:336–346` 又提供「保存」并退出。

影响：返回退出已经发生部分保存，按钮却暗示此前仍是草稿；切换点击动作还会增加 `savedRevision`，触发其他局部状态重新读取。

改法：已有实例采用即时应用加「完成」，或者全部编辑保持为草稿并统一保存。首次桌面添加保留 Android 配置结果返回，但明确区分创建和修改的生命周期。

验收：改任一字段后返回的结果一致；新建小组件可正确完成或取消；切换动作不意外重置其他未完成编辑。

### 08 · P2 · 数字输入的有效性不属于具体字段

证据：`addfood/AddFoodEditDialogs.kt:49–90` 通用数字弹窗允许 0；重量和份量调用方要求正数。确认后可能得到不可保存的页面，弹窗本身没有对应范围错误。

改法：传入字段约束或验证函数。重量、份量必须大于 0，营养素可以为 0；在当前字段呈现短错误，确认成功后才关闭。

验收：0、空值、小数、超限值都有符合字段含义的处理，不靠页尾说明解释禁用按钮。

## 同时改善 UX / DX / AX 的实现收敛

### A · 一个编辑状态对应一个保存对象

把记录、手动录入和预设编辑共用的草稿与校验抽出，页面仅保留弹窗可见性等临时状态。保存、加入预设、退出确认都消费同一份有效数据。

- UX：不会出现屏幕已修改、操作却用旧值；退出结果一致。
- DX：共享字段约束、营养计算和提交规则，减少两份大表单的修复同步。
- AX：自动化读取和提交的是同一个对象，状态与操作结果可判断。

### B · 导航使用真实、统一的目的地

`MineRoute` 目前仅在自己的声明和标题映射中出现，实际页面通过 Activity 跳转。`PageColumn` 也没有调用方；其 top padding 实现不能直接作为现有页面遮挡的证据，但属于容易误用的遗留抽象。

先明确当前 Activity 导航为事实来源，集中目的地名称和打开方法，移除经过确认无用的路由与页面壳；无需为了审美立刻重写整个导航栈。

- UX：入口名称、返回行为和配置后恢复上下文一致。
- DX：避免修改无人使用的路由后误以为页面已更新。
- AX：一个目的地只有一个可识别名称和进入契约。

### C · 让页面文件对应职责

`SettingsScreens.kt` 当前 1742 行，混合模型配置、资料、目标、外观、关于、更新和通用表单；`StatsViewModel` 定义在 `TodayViewModel.kt:220`，同时被统计与推荐使用。

按现有页面职责拆文件，先整理模块归属，再按实际状态依赖拆 ViewModel。拆分应服务于独立理解和验证，不按行数机械拆出几十个小文件。

- UX：局部调整较少影响其他页面，状态变化更稳定。
- DX：可按文件名定位，减少无关上下文和重复实现。
- AX：搜索结果与任务边界一致，降低误改风险。

### D · 统一控件语义，而不是删到只有图标

`LiquidBottomTab` 只暴露 `Role.Tab`，没有接收或设置 selected 状态；视觉选中层独立绘制。应把选中状态传入 tab 并暴露语义。`PickerField` 的 disabled 仅在点击回调内部拦截，也应核查可访问性状态。

为自定义字段补充一致的名称、角色、选中/禁用/错误/忙碌状态；可见文案精简时保留完整的语义标签。已有统计管理的 custom accessibility actions 是可复用的好基础。

- UX：读屏与触摸的状态一致。
- DX：公共组件承担状态契约，页面不用逐处补救。
- AX：UI Agent 能区分当前页、不可操作项和成功状态，不依赖像素颜色猜测。

### E · 收敛效果与页面尺寸策略

录入子页普遍使用 `AddFoodSheetHeight = 780.dp`；底栏固定 56dp，并以屏宽比例分配。现有玻璃、模糊和降级逻辑跨主 Activity、二级壳与自定义控件分布。仅凭这些实现不能断言必然裁切或掉帧，但会扩大验证范围。

用可用窗口高度和 IME 统一安排录入内容与操作区；统一效果能力策略、层级和降级入口，保留已有开关与高级调节。先验证最窄窗口和最低支持版本，再决定删减哪些动画实现。

- UX：键盘、大字体和系统导航变化不影响主要操作。
- DX：减少每页手写 padding、效果条件和固定尺寸补丁。
- AX：控件位置和可达状态更稳定，页面无需额外解释才能操作。

## 推荐实施顺序与不回退条件

1. 先修复记录完整性、草稿与预设对象问题；为这些数据行为补充必要的回归测试。
2. 统一缺配置跳转、字段校验、保存与返回契约；修正真实统计数值和控件语义。
3. 重排添加、今日和推荐三个高频流程，保持原有入口能力可达，再删除重复标题和说明。
4. 收敛设置分组与高级页面，按需要展开来源、指南、公式和技术设置。
5. 最后整理共享编辑组件、文件归属、遗留路由及效果策略，避免把大规模技术迁移与视觉调整捆绑。
