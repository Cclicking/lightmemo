# 识别日志模式

入口：关于 → 诊断信息 → 识别日志 → 日志模式。默认关闭；开启后重新执行识别，可在同一页面导出全部保留事件。关闭开关保留已有日志，清空操作独立于诊断统计。

日志最多保留最新 300 条，按时间顺序导出 JSON，重启后继续保留。存储在应用的 `noBackupFilesDir`，不参与 Android 系统云备份或设备迁移，不自动上传。磁盘写入由应用 IO 协程串行执行，识别过程只投递事件；读写失败会在页面提示，并允许尝试导出内存中的日志。

记录内容：随机任务编号、时间、阶段开始/结束、任务成功/失败/取消/等待选择、模型调用次数，以及模型/USDA 请求的开始、响应头、响应体读取完成、错误类别。模型类别和服务商仅使用固定枚举，未知配置归为“其他”，不保存用户填写的字符串。API 返回时还提取数值 token 用量和是否有思考内容。

不保存 API Key、URL、请求头、照片或路径、食物名称、提示词、接口响应正文、思考正文或异常原文。

排查两分钟等待：

1. 开启日志，使用同一张照片重新识别，等待完成或出现错误后导出。
2. 用 `task` 分组；按 `timestampMs` 查看事件，`elapsedMs` 是任务开始后的累计毫秒数。
3. `PHASE_END.durationMs` 是该次阶段耗时。阶段可并行或嵌套，不能将所有阶段简单相加当作总耗时。以 `TASK_END.durationMs` 为总耗时。
4. 同一 `request` 的 `HTTP_HEADERS.durationMs` 是从发起请求到收到响应头的时间，`HTTP_BODY.durationMs` 是从发起请求到读完整个响应的累计时间，两者相减才是响应头之后的读取时间。它们包含连接、上传、服务端处理和网络等待，不能单独证明模型推理耗时；响应头也不是首个 token 的时间。
5. `HTTP_ERROR.error` 区分超时、网络异常、取消和其他错误。即使营养查询或模型复核随后使用回退路径，失败请求仍保留。`reasoningPresent`/`reasoningTokens` 仅在返回对应元数据时可用，缺失不能据此断定已关闭思考。
6. `HTTP_START.thinkingDisabled=true` 表示本次模型请求显式关闭思考；仍需结合响应中的思考 token 检查服务端实际行为。USDA 请求的 `candidateLimit` 表示发送给服务端的候选上限，自动匹配为 8，手动候选搜索按界面请求数量设置。

识别尚未结束时也可导出日志；最后一条开始事件和时间可帮助判断当前卡在哪一步。日志不记录开始之前已经发生的操作；超过 300 条时，较早任务的开头可能被淘汰。
